# 新增普通聊天与异常恢复

1. 两端均更新到 0.2.9，连接服务器，等待同步完成。
2. 点击左侧“＋ 新增会话”。服务器确认空白聊天页后，本地显示“新会话”。
3. 输入文字，按 Ctrl+Enter 或点击“发送”。首条消息确认后，程序绑定正式聊天编号并显示真实回复。
4. 左侧最近列表可以切回旧聊天，其本地草稿会恢复；再选择新聊天可继续对话。

空白聊天可能尚未保存到 Claude 历史，首条消息后才出现正式记录。已处于空白聊天时，重复点击保留该页及输入文字，不发送占位消息。

## 草稿与状态

- 草稿按服务器与会话区分。服务器已有草稿时，先处理“取回服务器草稿”，工具不会覆盖它。
- 正在回复、取回草稿或上一项操作结果不明确时，暂停新建和切换。
- “清空本地草稿”只清编辑内容，不能解除未知发送或新建状态。
- 超时或断线后先点击“切换 / 重连”，再刷新。程序按原编号核对，不自动重发。
- 已提交消息读取到后才清除对应原稿，随后编辑的新文字继续保留。
- 若日志损坏、无法关联页面或操作一直未知，请保留文字和两端数据目录进行维护核对，不要删除操作记录强制解锁。

## 适用范围

本期只支持普通聊天，不包括项目内新聊天或 Code 任务创建。入口和页面需要能被服务器 Windows 无障碍接口识别；旧服务器或不支持页面下按钮不可用。

同一服务器用户会话只允许一个写入控制端。控制权短期保留约 60 秒，其他客户端可查看；原操作未知时不能绕过核对。请避免在服务器同时人工切换页面。原应用不提供共同事务，无法保证任意外部并发点击下的原子操作。

日常可断开远程桌面，但需保留已登录的 Windows 用户会话、Claude 和 Agent。注销、锁屏、重启无人登录与断开远程桌面不同。

## 数据升级

0.2.9 使用带版本的草稿格式，读取旧格式时保留 local-draft.dat.v1.bak。配对继续使用原数据目录。回退旧版前先备份草稿和操作记录；已真实创建的聊天和发送的消息不会随回退撤销。

操作记录受 Windows 当前用户加密保护，未解决的发送可能需保存原文核对。诊断默认不打印这些原文或配对密钥。去重信息保留至维护上限，达到上限时停止接收新写操作并提示维护。
