# 架构与数据边界

## 组成

- `Client.cs`：Windows 本地窗口、最近会话、草稿和送达核对。
- `Host.cs`：服务器配置、后台启动参数及守护入口。
- `Agent.cs`：TLS 桥接、认证、连接容量和串行桌面操作队列。
- `DesktopProbe.cs` / `DesktopAdapter.cs`：当前 Windows 用户 Claude 主窗口的无障碍读取与操作。
- `Protocol.cs`：消息格式、长度帧、证书指纹校验及 Windows 当前用户加密。
- `ApplicationInfo.cs`：版本和共用作者弹窗。
- `Cdp.cs`：历史诊断适配源码。默认发布路径使用 Windows 无障碍接口，不开启 Claude 调试通道。

## 一次发送

客户端保留原始草稿，捕获当前会话和确认编号边界，等待已有同步完成后提交一次。服务器核对会话、已有草稿及操作记录，再填入原应用并调用唯一的可用发送按钮。

客户端只有在同一会话读到编号更新且正文匹配的用户消息后才确认送达。显示层只兼容已经实现的段落与代码围栏差异；不能匹配时保留核对状态，不自动重发。单行末尾空白在客户端提交前处理，内部空行和代码缩进不作全局裁剪。

## 数据与限制

配对、身份和草稿保存在各自 `%LOCALAPPDATA%` 数据目录，按当前 Windows 用户加密。操作记录保留请求编号、摘要和阶段，未知提交结果保持保守处理。

桥接依赖服务器正确的用户会话和 Claude 界面。断开远程桌面与注销、锁屏、重启无人登录不是同一场景。无障碍界面还可能只暴露当前已加载的一部分消息，因此最近列表与已读消息不等于完整账号历史。
